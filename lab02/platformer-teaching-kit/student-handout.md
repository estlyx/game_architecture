# Практика: где заканчивается движок и начинается игра

Работайте по одному или в парах. Исходная игра: герой, три платформы и монетка. Инструкция сборки находится в seminar.md, готовая версия — godot/04_coin.

## Обязательная часть

1. Запустите игру и соберите монетку.
2. Измените высоту прыжка. До запуска запишите прогноз, после запуска — наблюдение.
3. Переназначьте прыжок на другую клавишу через Input Map. Сохраните имя действия jump.
4. Отключите коллайдер героя, наблюдайте результат, затем восстановите его.
5. Добавьте вторую монетку как экземпляр сцены. Проверьте счёт 2.

## Критерии зачёта

Игра запускается. Студент объясняет результат экспериментов, различает изображение и коллайдер, показывает привязку действия jump и путь сигнала collected. Изменение цвета или картинки само по себе не заменяет объяснение.

## После семинара: карта модулей v0.1

Составьте карту из 4–6 частей для своей игры. Для каждой укажите ответственность, вход или публичную операцию, разрешённые зависимости. Отдельно отметьте то, что предоставляет выбранный движок. Не называйте каждый узел сцены модулем движка автоматически.

Пример записи: «Контроллер героя получает действия move_left / move_right / jump, задаёт скорость тела и использует API столкновений. Он не обращается к тексту счёта».

Запишите одно решение: требование, выбранная граница, причина, цена изменения. Например: «Нужно переназначать клавиши. Используем имена действий Input Map. Поддерживаем таблицу привязок и избегаем прямой проверки Space в логике прыжка».

Использование ИИ укажите одной фразой: с чем он помог и как вы проверили результат.
