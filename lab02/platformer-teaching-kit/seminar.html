Семинар: один платформер в Godot

Цель: студент запускает маленькую игру, находит ввод, движение, столкновения и связь через сигнал, затем объясняет границу между кодом игры и возможностями движка.

Основной маршрут рассчитан на 80 минут после подготовки компьютеров. Установку и загрузки выполните до занятия. Для преподавателя, который впервые открывает Godot, предусмотрите отдельную спокойную репетицию: это время не включено в 80 минут.

До занятия: подготовка MacBook Air M3

  1. Скачайте обычную версию Godot 4 для macOS с https://godotengine.org/download/macos/. Вариант .NET здесь не нужен: используем GDScript. Официальная сборка поддерживает Apple Silicon.
  2. Распакуйте приложение. Откройте Godot обычным способом. Установку в Applications можно выполнить вручную, но для работы достаточно распакованного приложения. Если macOS блокирует запуск, используйте официальную инструкцию Godot по запуску на macOS, не отключайте защиту системы целиком.
  3. Распакуйте этот комплект в папку, где вы будете работать. Сохраните исходный архив как запасную копию.
  4. В менеджере проектов Godot нажмите Import, выберите godot/04_coin/project.godot, затем откройте проект. Если появляется выбор редактирования, выберите Edit. Подождите окончания первого импорта SVG.
  5. Кнопкой ▶ Run Project справа сверху запустите игру. Клавиатурный эквивалент: F5, на Mac часто Fn+F5. Стоп: кнопка ■ или F8 / Fn+F8. У некоторых версий игра открывается внутри редактора, у других в отдельном окне. Нажмите внутри игры, чтобы она получила фокус.
  6. Пройдите путь: вправо до первой платформы, прыжок, переход на вторую, затем на третью. Монетка находится над третьей. Прыгать удобнее ближе к краю платформы. Проверьте, что после подбора счётчик показывает 1, а R возвращает уровень и счётчик в начальное состояние.
  7. В меню Debug включите Visible Collision Shapes, снова запустите игру. Убедитесь, что можете показать границы физических тел. Затем отключите этот режим.
  8. Репетируйте три эксперимента из раздела ниже. Слайды откройте отдельно. Не показывайте заметки с готовыми ответами на проекторе.

Если у студентов нет установленных редакторов, проведите демонстрацию с прогнозами аудитории и выдайте практику после занятия. Не расходуйте семинар на параллельную установку всего окружения.

Два способа работы

Сборка с нуля: создайте собственный проект и выполните шаги 0–5. SVG возьмите из godot/04_coin/assets. Не копируйте готовые сцены в свой проект, если хотите пройти сборку самостоятельно.

Показ с восстановлением: импортируйте готовые этапы 00–04 как отдельные проекты. При ошибке остановите текущую игру и откройте следующий готовый этап через менеджер проектов. Папка этапа целиком самодостаточна.

Ориентиры: сцена — сохраняемое дерево узлов, узел — объект с определённой ролью, экземпляр сцены — её размещение внутри другой сцены. Inspector справа показывает свойства выбранного узла, FileSystem показывает файлы проекта, Scene показывает дерево текущей сцены. Названия панелей могут немного различаться между версиями и языками интерфейса.

Шаг 0. Комната и пол

Вопрос до работы: «Если нарисовать пол, будет ли он удерживать героя?»

  1. В менеджере Godot выберите Create. Название: OnePlatformer. Выберите новую пустую папку. Renderer: Compatibility. Если предлагается Version Control Metadata, для этого упражнения можно выбрать None.
  2. Откройте Project → Project Settings → Display → Window. Задайте viewport width 960, height 600. При необходимости используйте поиск viewport_width / viewport_height. Для Stretch → Mode выберите canvas_items.
  3. В Project Settings → Rendering → Environment измените Default Clear Color на тёмный, например #0e1624. Это влияет только на вид фона.
  4. В FileSystem создайте папки assets, scenes, scripts. Скопируйте три SVG из godot/04_coin/assets в вашу assets через Finder. Вернитесь в редактор и дождитесь импорта.
  5. Создайте сцену с корнем StaticBody2D. Переименуйте корень в Platform. Сохраните как scenes/platform.tscn.
  6. Добавьте к Platform узел Sprite2D. Перетащите platform.svg из FileSystem в свойство Texture в Inspector. Изображение имеет размер 180 × 24.
  7. Добавьте к Platform узел CollisionShape2D. В свойстве Shape выберите New RectangleShape2D. Нажмите на созданный ресурс и установите Size (180, 24). Положение дочерних узлов оставьте (0, 0).
  8. Выберите Platform. В Collision Layer включите только слой 1, в Collision Mask только слой 2. Слои — номера переключателей, а не числовые маски: герой позже будет на слое 2.
  9. Создайте новую сцену Node2D, назовите корень World, сохраните как scenes/world.tscn.
  10. В World добавьте StaticBody2D, имя Ground, Position (480, 552). Layer только 1, Mask только 2. Под ним добавьте Sprite2D с platform.svg, Scale этого Sprite2D = (5.333333, 1). Добавьте к Ground CollisionShape2D с новым RectangleShape2D, Size (960, 24). Scale самого Ground и CollisionShape2D оставьте (1, 1). Так изображение пола растягивается отдельно, а размеры физической формы заданы явно.
  11. Нажмите Run Project и при запросе главной сцены выберите текущую world.tscn.

Должно получиться: пол внизу окна. Героя ещё нет. Готовый аналог: 00_room.

Что сказать: «Sprite2D отвечает за вид. CollisionShape2D задаёт геометрию, которую использует физика. Это два разных представления одного объекта».

Шаг 1. Герой падает

  1. Создайте новую сцену с корнем CharacterBody2D, назовите Player. Сохраните как scenes/player.tscn.
  2. Добавьте Sprite2D, Texture = hero.svg.
  3. Добавьте CollisionShape2D, Shape = New RectangleShape2D, Size (36, 44). Оба дочерних узла в позиции (0, 0).
  4. Для Player установите Collision Layer только 2, Collision Mask только 1.
  5. В панели Node → Groups добавьте Player в группу player. Это имя проверяет монетка. В новых версиях панель групп может быть отдельной вкладкой рядом с Signals.
  6. Прикрепите к Player скрипт scripts/player.gd. Отключите шаблон или полностью замените созданный текст содержимым godot/01_falling/scripts/player.gd.
extends CharacterBody2D
@export var gravity: float = 1400.0

func _physics_process(delta: float) -> void:
    if not is_on_floor():
        velocity.y += gravity * delta
    move_and_slide()
  1. Сохраните сцену. Вернитесь в World. Перетащите туда player.tscn, Position (96, 180).
  2. Запустите проект, а не отдельную сцену героя. При запуске отдельного Player пола не будет.

До запуска спросить: «Кто в этом фрагменте задаёт гравитацию, а кто проверяет столкновение?»

Должно получиться: герой падает и останавливается на полу. Клавиши пока ничего не делают. Аналог: 01_falling.

Объяснение: ось Y направлена вниз. Наш код увеличивает вертикальную скорость. Метод Godot move_and_slide() перемещает тело с обработкой столкновений. CharacterBody2D не получает гравитацию автоматически. delta — длительность шага в секундах. Пока достаточно этой роли, подробное устройство игрового цикла будет на следующей теме.

Шаг 2. Движение и прыжок

  1. Откройте Project → Project Settings → Input Map. Создайте действия с точными именами:
Имя Клавиши
move_left A и Left
move_right D и Right
jump Space
restart R

Добавляйте событие кнопкой + возле действия. Можно нажать нужную клавишу в окне назначения. Для A / D / R удобно выбрать Physical Key, чтобы управление не зависело от раскладки. Удалять встроенные действия ui_* не нужно.

  1. Полностью замените player.gd содержимым godot/02_jump/scripts/player.gd. Полный текст находится также ниже. Не вставляйте его после прежнего кода: в файле должна остаться одна функция _physics_process.
extends CharacterBody2D
@export var speed: float = 240.0
@export var jump_velocity: float = -560.0
@export var gravity: float = 1400.0

var spawn_position: Vector2

func _ready() -> void:
    spawn_position = global_position

func _physics_process(delta: float) -> void:
    if not is_on_floor():
        velocity.y += gravity * delta

    var direction := Input.get_axis("move_left", "move_right")
    velocity.x = direction * speed

    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity

    move_and_slide()
    global_position.x = clampf(global_position.x, 20.0, 940.0)

    if global_position.y > 700.0:
        global_position = spawn_position
        velocity = Vector2.ZERO
  1. В World переместите Player в (96, 480). Сохраните. Запустите проект.
  2. Проверьте движение и прыжок. Повторное нажатие в воздухе не должно давать второй прыжок. R заработает после подключения world.gd на шаге 5. В готовых этапах перезапуск уже подключён.

Код читать четырьмя действиями: применить гравитацию, узнать направление, задать скорость прыжка при стоянии на полу, попросить движок переместить тело. Возврат после падения и ограничение X — служебная защита для демонстрации, отдельно их не разбираем.

Важно: velocity измеряется в пикселях в секунду. Не умножайте её ещё раз на delta перед move_and_slide(). В нашем коде delta нужна для изменения скорости под действием ускорения.

Шаг 3. Три платформы из одной сцены

  1. В World перетащите platform.tscn ещё три раза. Создайте экземпляры с параметрами:
Имя Position Scale
Platform1 (290, 456) (1, 1)
Platform2 (490, 360) (1, 1)
Platform3 (710, 264) (1, 1)
  1. Создавайте платформы из platform.tscn, а не дублированием Ground: у пола другая ширина. Scale новых экземпляров оставьте (1, 1).
  2. Сохраните, запустите, доберитесь до третьей платформы. Перед прыжком подходите к краю предыдущей.

Вопрос: «Если изменить исходную сцену Platform, какие экземпляры изменятся? А если изменить только Position одного экземпляра?»

Вывод: повторно используется сохранённая сцена объекта. Это ещё не выделение собственного движка, но уже понятный механизм композиции. Аналог: 03_platforms.

Шаг 4. Монетка сообщает о подборе

  1. Создайте сцену с корнем Area2D, назовите Coin, сохраните как scenes/coin.tscn.
  2. Добавьте Sprite2D с coin.svg.
  3. Добавьте CollisionShape2D с CircleShape2D, Radius 14.
  4. На корне Coin отключите все Collision Layer, в Collision Mask оставьте только 2. Монетка отслеживает героя, но не является твёрдым препятствием.
  5. Добавьте корень Coin в группу coins через Node → Groups.
  6. Прикрепите scripts/coin.gd. Скопируйте содержимое из godot/04_coin/scripts/coin.gd:
extends Area2D
signal collected

var taken: bool = false

func _ready() -> void:
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if taken or not body.is_in_group("player"):
        return
    taken = true
    collected.emit()
    queue_free()
  1. Сохраните, поместите экземпляр Coin в World, Position (710, 208).

Сигнал body_entered подключает сам скрипт. Не подключайте его повторно через редактор. taken защищает от повторного подбора до фактического удаления узла. queue_free() удаляет узел безопасно в конце обработки кадра.

Прогноз: «Сейчас монетка исчезнет. Появится ли счёт?» Ответ: счёт ещё никто не хранит. Сам сигнал не создаёт получателя.

Шаг 5. Уровень связывает сигнал и счётчик

  1. В World добавьте узел CanvasLayer, имя HUD. Под HUD добавьте Label, имя Score, Text = Монет: 0. В Layout / Transform установите Position (28, 112). Для читаемости задайте Theme Overrides → Font Sizes → Font Size 22.
  2. При желании добавьте под HUD Label Title с текстом Один платформер, Position (28, 22), размер шрифта 28. Ещё один Label Instructions: A / D или стрелки, пробел, R: заново, Position (28, 68), размер 18. Эти две подписи не обязательны для логики.
  3. Прикрепите к корню World скрипт scripts/world.gd. Вставьте содержимое из готового этапа 04:
extends Node2D
var score: int = 0
@onready var score_label: Label = $HUD/Score

func _ready() -> void:
    for coin in get_tree().get_nodes_in_group("coins"):
        coin.connect("collected", _on_coin_collected)

func _on_coin_collected() -> void:
    score += 1
    score_label.text = "Монет: %d" % score

func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("restart"):
        get_tree().reload_current_scene()
  1. Запустите. Подберите монетку. Счётчик должен увеличиться ровно на 1. Нажмите R: уровень перезагрузится, монетка вернётся, счёт станет 0.
  2. Для проверки повторного использования остановите игру, дублируйте экземпляр Coin в World сочетанием Cmd+D или через контекстное меню Duplicate. Второй экземпляр поставьте в (490, 304). Запустите и соберите обе монетки. Ожидаемый счёт 2.

В этом небольшом примере World знает путь $HUD/Score и связывает получателей. Монетка о HUD не знает. Подписка выполняется один раз для монеток, уже находящихся в сцене. Динамическое создание монеток в ходе игры потребовало бы отдельного подключения — это за пределами упражнения.

Три обязательных эксперимента

А. Высота прыжка

Остановите игру. В World выберите Player. В Inspector измените экспортированное свойство Jump Velocity с -560 на -720. Спросите, станет прыжок выше или ниже, затем запустите. Модуль числа больше, начальная скорость вверх выше, прыжок выше. Физический движок мы не меняли. Верните -560.

Если свойство не видно, откройте скрипт и убедитесь, что перед переменной стоит @export. Если изменение в коде не влияет на результат, проверьте, нет ли сохранённого переопределения свойства в Inspector экземпляра.

Б. Клавиша прыжка

Остановите игру. Project Settings → Input Map → jump. Добавьте J и удалите Space из этого действия. В игровых скриптах ничего не меняйте. Запустите, проверьте J и пробел. Верните Space и удалите J.

Прогноз: «Где мы будем менять код героя?» Ответ: в этом эксперименте достаточно изменить привязку действия. Имя jump служит границей между устройством и правилом игры.

В. Изображение и столкновение

Для самого ясного показа используйте готовый этап 02_jump. Откройте исходную сцену player.tscn, выберите CollisionShape2D, включите Disabled, сохраните и запустите проект. Герой провалится сквозь пол и после выхода за нижнюю границу вернётся к старту. Повторение падения предусмотрено защитой в player.gd.

Верните Disabled = Off. Теперь у Sprite2D отключите Visibility → Visible. Запустите. Герой невидим, но тело продолжает сталкиваться с полом. Для наблюдения включите Debug → Visible Collision Shapes. После опыта верните Visible = On и отключите отладочное отображение.

Итоговый вопрос: «Что нужно было изменить: рисунок, геометрию столкновения или правило движения?»

Если есть только 50 минут

Не собирайте проект с нуля. 5 минут играем в этап 04, 10 минут разбираем Player, 15 минут проводим три эксперимента, 10 минут показываем сигнал монетки и дублируем её, 10 минут составляем таблицу «игра / движок» и обсуждаем ответы. Сборку с нуля выдаём как самостоятельную работу.

Симптом Проверка

Минимальная репетиция перед аудиторией

  • Все пять проектов открываются и запускаются на вашем Mac без ошибок Debugger.
  • Герой достигает монетки, счёт меняется, R восстанавливает уровень.
  • Пройдены три эксперимента, затем исходные свойства восстановлены.
  • Вторая монетка увеличивает счёт до 2.
  • Окно игры и размер текста удобны для проектора.
  • Вы можете открыть запасной этап без поиска по папкам.

Это критерии готовности к показу, а не утверждение, что запуск уже проверен в среде подготовки. Автоматическая проверка ресурсов выполнена отдельно. Дополнительный запуск через Godot описан в checks/README.md.
